Централизация — клиент для Windows x64, версия 1.1.0.5

ЗАПУСК
1. Скопируйте или распакуйте всю папку Release_web_1.1.0.5 на Windows-ПК.
2. Запустите Start_Client.bat обычным двойным щелчком.
3. Откроется браузер: http://127.0.0.1:5176/login.
4. На странице входа укажите доступный с этого ПК адрес CentralServer и войдите.
   Адрес по умолчанию: http://10.10.69.56:5120.
   При необходимости замените его адресом своего CS. Сохранённый ранее адрес
   в этом браузере имеет приоритет над адресом по умолчанию.

Оставляйте окно Client открытым. Для остановки нажмите в нём Ctrl+C.
Повторный запуск этой же версии открывает браузер с уже работающим клиентом.
При первом запуске Client сам настроит автообновление. Отдельный bootstrap
и права администратора не нужны. Распакуйте пакет в папку, доступную вам для записи.
Когда на CS опубликована новая версия, в Client появится уведомление.
Проверка выполняется при запуске и попытке входа. На странице входа также есть
кнопка «Проверить обновление». Постоянного опроса обновлений в фоне нет.
Сохраните незавершённые изменения и нажмите «Обновить»: пакет будет проверен
по подписи, установлен, Client перезапустится на том же локальном порту.
При неудаче установки помощник попытается восстановить предыдущую версию.
Для получения обновлений нужен доступ к http://10.10.69.56:5120.
Настройка адреса CS на странице входа относится к рабочим запросам интерфейса;
адрес центра обновлений задан отдельно в updater-bootstrap.json.
Все файлы, включая wwwroot, должны оставаться вместе.

ТРЕБОВАНИЯ
Windows x64 с поддержкой .NET 10 (например Windows 11), современный браузер
Chrome или Edge, сетевой доступ к CentralServer. Node.js, npm, отдельная установка
.NET и права администратора для запуска клиента не требуются: runtime включён
в CentralisationClient.exe. На первом запуске Windows может проверять EXE;
файл не имеет цифровой подписи издателя.

НАСТРОЙКИ
Локальный порт 5176 можно изменить в строке CLIENT_PORT файла Start_Client.bat.
Если порт занят другой программой или старой версией клиента, закройте её
либо выберите свободный порт. При смене порта потребуется снова войти:
браузер хранит настройки и сессию отдельно для каждого локального адреса.
Пакет не содержит логинов, паролей, токенов, камер или баз данных.
Папка updater и updater-bootstrap.json должны оставаться в дистрибутиве.
Внешний помощник и резервные копии хранятся в вашем LocalAppData\CentralisationUpdater.
После первого запуска client-updater.local.json содержит локальные пути и настройки;
не копируйте его другому пользователю или в новую папку. Client создаст свой файл сам.

Клиент обращается только к CS; локальный host раздаёт готовый интерфейс
только на 127.0.0.1. CS и Neuro этот bat не запускает и не обновляет.
Администратор компании может открыть настройки своей точки, вкладку
«Обновление Server», проверить и подтвердить установку. Пакет передаёт ЦС
на приёмник Server по HTTPS5122; обычный API точки остаётся на5120.
Для просмотра связанных зон поверх архивных кадров CS должен поддерживать
API zone-frame из обновления от 11.10.2026. Сама Windows-сборка CS не меняет.

ПРОВЕРКА ПАКЕТА (PowerShell, необязательно)
Get-FileHash .\CentralisationClient.exe -Algorithm SHA256
Ожидаемые SHA256 для файлов перечислены в SHA256SUMS.txt.
В release-info.json указаны состав и параметры сборки.
Лицензии runtime и используемых npm-пакетов находятся в папке licenses.

Runtime: https://learn.microsoft.com/dotnet/core/deploying/single-file/overview
